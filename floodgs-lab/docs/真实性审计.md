## 1. 逐项审计

### 1.1 地形 —— 完全是虚构的

`L1_scene/build_scene.py` 里每一处高程都是公式算出来的：

```python
z_bed = 90.0 - 0.008 * x          # 河底纵剖面：西端 90 m，东端 88.4 m，纵坡 0.8%
RIVER_HALF_W = 11.0               # 河槽半宽 11 m → 河宽 22 m
LEVEE_TOP_OFFSET = 4.2            # 堤顶高出河底 4.2 m
YARD_OFFSET = 2.4                 # 厂区地面高出河底 2.4 m（比堤顶低 1.8 m）
BREACH_X, BREACH_W = 110.0, 22.0  # 溃口位置和宽度
```

**这意味着**：这个场景在现实中没有对应地点。它只是一个"物理上讲得通"的假想厂区。

**换成真实地形要改的**：只需替换 `assets/scene.npz` 里的 `z` 和 `landuse` 两个数组，
下游 L2/L3/L4 一行都不用改。已经有现成的导入脚本：`L1_scene/import_dem.py`。

所以你论文里不能写"在 3DGS 重建场景上实验"—— 目前只能说"在 3DGS 表示的合成场景上验证方法链路"。

### 1.3 水流 —— 真实求解，但模型有档次之分

求解器是二维浅水方程（SWE）的**局部惯性简化格式**（Bates 2010 / de Almeida 2012，
LISFLOOD-FP 同源）。这是洪水淹没模拟的工程标准，但要知道它的边界在哪：

| 能算准 | 算不准 |
|---|---|
| 淹没范围、最大水深（误差 10–20%） | 溃口射流的三维结构 |
| 缓变流的速度场 | 冲击力峰值 |
| 水量平衡 | 涡流、掺气、水跃细节 |
| 干湿边界的进退 | 局部流速的瞬时波动 |

**实际跑出来的量**：

| 量 | 数值 | 怎么来的 |
|---|---|---|
| 入流总量 | 26.08 万 m³ | 上游过程线积分（峰值 440 m³/s） |
| 出流总量 | 25.88 万 m³ | 边界通量累积 |
| 蓄水量 | 1.04 万 m³ | 全场 h 求和 × 面积 |
| 闭合误差 | **−0.2%** | (初始+入流−出流−蓄水)/入流 |
| 峰值水深 | 3.41 m | 全场 h 最大值 |
| 峰值流速 | 13.9 m/s | 出现在溃口射流，**这个数偏高**，见 §3.4 |

水量闭合 −0.2% 说明数值上可信。这是这个仓库里最硬的一个指标。

### 1.5 "撞击"与"被冲走" —— 完整推导

这里没有"撞击"这个概念，因为**没有碰撞检测**。车辆是被**流体拖曳力**推走的，
不是被水"撞"走的。区别在于：撞击是瞬时脉冲，拖曳是持续作用力。

判据是三条力的平衡（`L3_assess/assess.py: vehicle_state`）：

```
浮力      F_b = ρ_w · g · 0.6 · L · W · h_s        (h_s = min(h, H)，0.6 是车厢进水折减)
拖曳力    F_d = ½ · ρ_w · Cd · (W · h_s) · u²       (迎流面积 = 车宽 × 浸没深度)
法向力    N   = max(0, m·g − F_b)                   (浮起后 N=0，即失去摩擦)
摩阻力    F_f = μ · N
```

判定顺序（**先浮起，再滑移**）：

| 条件 | 判定 | 物理含义 |
|---|---|---|
| `F_b > m·g` | floating（漂浮） | 车浮起来了，摩擦彻底消失 |
| `F_d > F_f` | sliding（滑移） | 还没浮，但推力大于摩擦 |
| 否则 | stable | 站得住 |

**代入小汽车的实际数字**：

| 水深 | 浸没体积 | 浮力 | 自重 | 结论 |
|---|---|---|---|---|
| 0.2 m | 0.97 m³ | 9.5 kN | 14.2 kN | 压得住 |
| **0.3 m** | 1.46 m³ | **14.3 kN** | 14.2 kN | **临界** |
| 0.5 m | 2.43 m³ | 23.8 kN | 14.2 kN | 浮起 |

**临界水深约 0.3 m**。这个数和文献里"小汽车涉水 0.3–0.5 m 即危险"的经验值吻合。

漂起来之后怎么动（`simulate_vehicles`）：

```
a = F_d / m
v += a · dt      (dt = 0.5 s)
x += v · dt
若前方水深 < 0.15 m → 触底，v = 0（搁浅停止）
```

**是确定性的**：同样的输入，跑一百次结果完全一样。没有任何随机数。

**碰撞**（2026-10-25 补充）：车辆不是用中心点探测，而是用**车头**
（中心沿速度方向偏移半车长 2.25 m）探测建筑固壁。撞上则本步不移动、速度归零。
改前会直接穿墙，改后 **0/6 车辆、0/54 货物进入建筑**。

**附加质量**（2026-10-25 补充）：`m_eff = m + Ca·ρ·V_sub`，Ca=0.5。
小汽车在水深 0.5 m 时，等效质量从 1450 kg 增至 2665 kg，加速度降低约 45%。

### 1.6 不是 "3DGS 动态编辑"，但等价于它

你的问题问得很准。我现在的做法是：

```
仿真给出车辆新位置 → 在新位置重新生成这辆车的高斯 → 和静态场景合成 → 渲染
```

而 InsertAny3D / RAF 那类工作的做法是：

```
场景里已经有一组车的高斯 → 直接对这组高斯的 (xyz, rotation, scale) 施加刚体变换 → 渲染
```

**结果视觉上一样，技术路线不同。**

- 我的做法：**重建式**（每次从参数重新"长"出高斯）
- 他们的做法：**编辑式**（搬运已有的高斯）

区别在于：如果车是真实重建出来的（有真实纹理、车漆反光、车牌），
编辑式能保留这些细节，重建式会丢掉。

**所以当你有真实 3DGS 底座时，必须换成编辑式。** 具体怎么换见 §4。

### 2.2 三个关键算法（这是你论文的技术核心）

**① 3DGS → 高程场**

3DGS 没有"表面"，只有一堆各向异性的高斯。要得到 DEM，必须做投影：

```python
# 对每个水平网格 (i,j)，收集落在该格内的高斯
for each gaussian g in scene:
    i, j = int(g.x / dx), int(g.y / dy)
    bucket[j][i].append(g.z)

# 地面高程 = 该格内 z 的低分位数（避开树冠、电线、车辆）
z_ground[j,i] = percentile(bucket[j][i], 10)

# 建筑/物体高程 = 高分位数
z_top[j,i] = percentile(bucket[j][i], 95)
```

用低分位数而不是最小值，是为了抗离群点（漂浮的高斯噪声）。
**这一步的精度直接决定水深精度**，建议在已知点（如路口、台阶）上做校核，目标 RMSE < 0.1 m。

**② 3DGS → 语义**

两条路，选一条：

- **Gaussian Grouping**：用 SAM 的 2D 掩码监督高斯的 identity encoding，训练后每个高斯带类别。
  优点：一次训练，全场可用；缺点：要 GPU，要调参。
- **SAM2 + 多视角投影投票**：对每个高斯，把它的中心投影到 N 个视角，查 SAM2 掩码，
  多数投票决定类别。优点：不用训练；缺点：遮挡区不准。

**建议先用第二条**（快、可控），效果不够再上第一条。

**③ 物体位姿估计**

对分割出的车辆高斯子集：
- 位置 = 子集质心
- 朝向 = 子集协方差矩阵的主特征向量在水平面的投影角
- 尺寸 = 子集在三个主轴上的 3σ 范围

这三步都是闭式解，不需要神经网络。**这是你可以写成"方法"的部分。**

### 2.3 精度预期（别期待太高）

| 量 | 无人机 3DGS 能达到的精度 | 对仿真的影响 |
|---|---|---|
| 水平位置 | 2–5 cm（有 RTK）/ 20–50 cm（无） | 影响小 |
| 高程 | **5–20 cm** | **直接进水深，是主要误差源** |

**"高斯刚体变换"是必须做的一步**，因为它决定了你的渲染是不是真的在编辑 3DGS：

```python
def transform_gaussians(means, quats, scales, R, t):
    """对一组高斯施加刚体变换（SE3）"""
    new_means = means @ R.T + t
    new_quats = quat_multiply(quat_from_matrix(R), quats)   # 旋转四元数左乘
    return new_means, new_quats, scales                     # 尺度不变
```

仿真给出每帧的 `(R, t)`，对车辆高斯子集施加变换，再和静态场景合并渲染。
**这就是 InsertAny3D / RAF 那类工作的核心操作**，只是它们还额外解决"怎么造出这个物体"。
